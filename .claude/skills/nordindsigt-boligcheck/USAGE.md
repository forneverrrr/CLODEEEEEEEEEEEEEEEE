# BoligCheck — как запускать (продакшн-режим)

Положите содержимое этой папки в рабочую сессию так, чтобы путь был
`.claude/skills/nordindsigt-boligcheck/`, плюс `templates/` и `pipeline/` рядом.
Скилл подхватывается автоматически — специальной команды не нужно.

Если хотите, чтобы сессия была посвящена только отчётам, положите этот текст
в корень рабочей папки как `CLAUDE.md`:

```markdown
# BoligCheck — генерация отчётов (NordIndsigt)

Ты генерируешь BoligCheck-отчёты по методологии
`.claude/skills/nordindsigt-boligcheck/SKILL.md`. Правила — в
`references/rules.md`, со стабильными ID; ссылайся на ID, не на версии.
Отвечай на русском, если не указано иное.

## Workflow
Вход: адрес / ссылка (boligsiden, boliga, nybolig, edc, home.dk) / PDF в inbox/.
Выход: `reports/<адрес>/report.md`, статус `DRAFT — NOT FOR CLIENT` до моего
явного «утверждаю».

## Что нельзя нарушать (полные формулировки — в rules.md)
1. Право покупки проверяется до анализа объекта (LEGAL-1) — без него сделка
   не состоится, и это перевешивает любую находку.
2. Все документы продавца читаются как изображения, не текстом (DOC-4, DOC-5).
3. Research pass идёт ДО черновика, компы фильтруются заранее (RES-2, RES-3).
4. Каждый факт клиенту проходит через evidence ledger (EV-7); ничего не
   выдумываем (EV-3).
5. Каждый отчёт — DRAFT, пока я явно не утвердил (GATE-1).
6. При сомнении — спроси, не действуй по памяти.
```

## Зависимости

```bash
pip install -r pipeline/requirements.txt      # pdf2image, pillow, playwright
# системная: poppler-utils (pdftoppm) для рендера PDF в изображения
```

Фетчер документов (`pipeline/fetch_salgsmateriale.py`) требует открытого
сетевого доступа к сайтам мэглеров — в песочнице с закрытым egress он не
работает, это не ошибка скрипта.

## Порядок работы

1. Скидываете адрес, ссылку или PDF.
2. Получаете черновик со статусом DRAFT и Operator Appendix (инвентарь
   документов + evidence ledger).
3. Проверяете приложение, говорите «утверждаю» — только после этого собирается
   клиентская версия без DRAFT-баннера.
